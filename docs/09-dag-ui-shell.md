# DAG 交互外壳（2026-11 重构）

这份文档描述 DAG 页**现在的交互模型**，以及为什么不再是"左列表 + 右检查器"。

## 1. 布局

```
┌──────────────────────────────────────────────────────────┐
│ 顶栏（项目 / 资源 / 自动挡 / 标签页）                      │
├──────────────────────────────────────────────────────────┤
│                                                          │
│   canvas（整幅 DAG，全屏宽度）                            │
│                                                          │
│   ┌ 节点列表（可选浮窗，默认关闭）                        │
│   └ 节点详情（双击节点打开，可多开）                      │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

工作区网格只剩**一列**：画布。左列表与右检查器都搬进了浮窗，
画布宽度不再被列宽挤压，也就不存在"缩到 990px 以下列表消失"的断点问题。

## 2. 手势表

| 操作 | 结果 |
|---|---|
| 单击节点 | 选中（画布高亮 + 关联边强调 + 无关节点降透明） |
| 双击节点 | 打开该节点的**详情浮窗**（同一节点已开则提到最前） |
| 右键节点 | 选中并弹出**节点菜单**（含多级子菜单） |
| 右键空白 | 画布菜单（适应视图 / 放大 / 缩小 / 取消选中） |
| 拖动空白 | 平移；滚轮缩放（以指针为锚点） |
| 方向键 | 平移；`+` / `-` / `0` 缩放 / 适应 |
| `Esc` | 关闭菜单；再按清空选中 |
| 工具栏「节点列表」 | 开关左侧浮窗（默认关闭，关闭时不渲染 DOM） |

**双击不再打开轨迹**：轨迹属于低频操作，收在右键菜单里（`查看 Profile 追踪` /
`打开原生会话`）。

## 3. 浮窗家族

三种浮窗共享同一套视觉与行为：半透明底 + 发丝投影 + 可拖动标题栏 + `✕` 关闭。

| 浮窗 | 打开方式 | 特性 |
|---|---|---|
| 节点列表 | 工具栏开关 | 按**状态分选项卡**（计划/运行中/已完成/失败/候选…），每页签 200 条分页；半透明 + 8px 背景模糊 |
| 节点详情 | 双击节点 / 菜单「打开详情窗口」 | 5 个 tab：概览 / 编辑 / 执行 / 报告 / 统计；右下角可缩放（最小 360×220）；`—` 最小化为标题条；可多开对比，点击置顶 |
| 右键菜单 | 右键 | 支持任意层级子菜单（`优先级 ▸`），右侧空间不足时向左翻；`Esc` / 外部点击 / 执行后关闭 |

### 节点菜单项（按状态裁剪）

公共：打开详情 · 创建子节点 · 查看文件 · 查看 Profile 追踪 · 打开原生会话 · 复制节点 ID

| 状态 | 额外项 |
|---|---|
| planned | ▶ 启动节点、优先级 ▸ |
| running | ■ 取消运行、继续对话（仅 merge 节点） |
| completed（叶子未封存） | 继续对话 |
| completed | 创建合并节点 |
| proposed | 批准提案 / 拒绝提案 |
| failed | 重试、升级模型 |
| cancelled | 重试 |

规则集中在 `nodeActionsOf({status, childCount, sealed, isMerge})` 一处：
**菜单不自己判断状态**，避免再次出现"父节点也能继续对话"这类与 Host 谓词漂移的问题。

## 4. 事件边界

画布容器的 wheel 只在**目标不是浮窗**时才缩放：

```js
target.closest('.rl-rail-window, .rl-node-window, .rl-dag-menu, .rl-canvas-toolbar, .rl-canvas-replay')
```

否则浮窗内的滚动会变成画布缩放（这正是之前的 bug）。同理，右键处理器挂在
**容器**而不是 `<canvas>` 上，`preventDefault()` 覆盖整个画布区域。

## 5. 不变量（都有探针守着）

1. 10k 节点全量绘制，不截断到 300（`dag-canvas-selftest`）
2. 平移/缩放不触发 React 重渲染，只在节流后更新缩放百分比（并带 trailing flush）
3. 选中不挂载任何 DOM 卡片，浮窗是唯一的详情载体
4. tab 切分由 section 数量推导，**并集恰好覆盖全部 section**，不会漏渲染
5. 菜单项集合 = `nodeActionsOf` 的输出，没有第二处判断
6. 节点列表关闭时不产生 DOM，也不占网格列

## 6. 重启服务会中断当前会话（不是自动挡停止）

`dsh web` 承载着正在跑的 agent 会话。重启进程 = 杀掉会话，聊天窗口会显示
**"任务已停止"**——这是 Host 的行为，与插件的自动挡无关（自动挡的暂停文案是
"Host 重启后自动挡已停止，请确认后继续"，两者容易混淆）。

`scripts/restart-dsh.sh` 因此做了两件事：

1. **等端口真正释放**再启动：被 kill 的进程可能留下子进程占着 `:3081`，
   抢跑会得到 `EADDRINUSE`，于是出现"旧服务已死、新服务没起"的空窗——那段时间
   页面既连不上、会话也已被标停；
2. **清理残留监听者**（`ss -ltnp` 找 `:3081` 的 pid 并 `kill -9`），避免第二个
   dsh 实例启动失败。

仍会中断会话这一点无法避免：需要加载 Host/插件的新代码就必须重启。做法上应
**合并改动、一次重启**，并在重启前告知，而不是每改一处就重启一次。

## 7. 浮窗一致性（统一外壳）

页面里所有浮窗都来自同一个 `FloatWindow` 外壳，因此外观与能力一致：

| 能力 | 实现 |
|---|---|
| 半透明 + 背景模糊 | `background: bg-layer-1 @82%` + `backdrop-filter: blur(10px)` |
| 拖动 | 标题栏 pointer 事件（按钮区域不触发） |
| 缩放 | 右下角手柄，最小 320×200 |
| 最小化 | `—` 折叠成标题条，`▢` 还原 |
| 关闭 | `✕` |
| 置顶 | 点击窗口任意处（`onPointerDown`）→ 共用 z 计数器 +1 |
| 可选 tab | `tabs` / `tab` / `onTab` |

使用它的四个窗口：

1. **节点详情**（双击节点）
2. **节点列表**（工具栏开关，状态分页签）
3. **历史**（顶栏时钟图标：变更日志 + DAG 回放）
4. **变更详情**（WAL 行 → 完整记录）

它们都渲染在同一个层 `.rl-node-windows` 里（`position: absolute; inset: 0`，`pointer-events: none`），
所以置顶在四种窗口之间是互相比大小的，不会出现"节点窗口永远压住历史窗口"。

一致性由探针守住：`wal-ui-selftest` 断言历史窗口带 `rl-node-window` 类、有缩放手柄、
可拖动、可最小化；`node-window-selftest` 对节点列表做同样的事。
