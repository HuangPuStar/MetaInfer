# 最小复现优先

**何时触发**：复杂 bug 定位超过 2-3 轮未果，或失败场景庞大难以隔离。

## 规则

- 复杂 bug 先抽出最小脚本：单组件、固定种子、可独立运行。
- 二分删减输入规模/调用路径，直到 bug 消失或稳定复现——触发边界本身就是最强的诊断线索。
- 在最小复现上修复，再放回原场景验证闭环。
- 禁止在庞大端到端脚本里直接反复试错——每次运行成本高且无法隔离变量。
- 保存失败样本（输入种子 + 参数）供一键复现单个用例。

## 反模式信号

- 在数百行的端到端流程里改一次跑十分钟，循环多轮仍无法定位。
- "有时候错有时候对"却从未固定种子压缩复现。
