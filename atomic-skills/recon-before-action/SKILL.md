# 先侦察后执行

**何时触发**：接到任何明确指令——尤其是"直接去跑/直接去测/直接去改"这类催促式指令。

## 规则

- 第一步永远是侦察现状：环境、依赖、资源占用、已有产物、当前状态；然后再执行指令本体。
- 提出修改方案前先完成一轮只读取证，产出**事实清单**（现状、参考实现、既有结论）；方案必须长在事实之上。
- 事实逐条标注证据等级：直接可见 / 推断 / 待验证；引用只来自真正读过的位置，没读过就只给路径、不编行号。
- 侦察产出写入运行记录，供后续轮次直接复用，不重复侦察。
- 无准备的直接动手会导致在"准备↔侦察"之间反复横跳——这是可观测的最大浪费模式之一。

## 反模式信号

- 指令说"跑基准"，结果先花数轮装环境、找文件、查依赖，基准本身迟迟没跑。
- 方案里的"事实"实际是假设，一验证就塌。
