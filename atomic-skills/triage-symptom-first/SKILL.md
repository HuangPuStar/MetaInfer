# 先分类现象再处置

**何时触发**：任何失败/异常出现的处置起点。

## 规则

- 动手前先判现象类别，按优先级取第一个命中：**构建错 / 运行错 / 超时 / 结果错 / 无结果**——对策完全不同。
- **超时 ≠ 慢**：先细分超时来源——死锁或锁等待 / 轮询外部资源 / 网络或服务未就绪 / 预算截断 / 真计算慢。进程还在时先查进程、端口、日志状态，不立刻原样重跑。
- 每类根因预先定义处置动作：缩小复现 / 释放锁 / 加显式超时 / 换就绪探针 / 优化热点。
- 同一命令超时两次必须换策略，禁止第三次原样重跑。
- 不把环境问题、测试自身问题误判为被测对象的问题；验证脚本本身超时先修测试（可能死锁），别判"结果错"。

## 反模式信号

- 超时后直接加大超时参数继续等——真正的死锁永远等不到。
- 验收工具挂了却被当成被测系统错误去修系统。
