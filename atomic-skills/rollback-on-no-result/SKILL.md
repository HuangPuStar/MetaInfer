# 回滚触发条件

**何时触发**：改动失败后决定"回滚还是继续修"。

## 规则

- 回滚的真实触发是"**跑不出任何结果**"（系统崩溃、无法产出、环境被改坏）；不是"结果变差"。
- 结果变差走**带病修复**：先诊断为何无效再改；同一命令无脑重跑不超过 2 次。
- 同一错误连续 2 次同因复现 → 回滚后再诊断，不在坏状态上继续叠改。
- 回滚后必须补根因分析再重新假设，禁止直接重复原方案——否则是原路重踩。
- 回滚后**仍然**跑不出结果 → 问题在环境不在代码，转环境排查。

## 数据画像

- 显式回滚前的现象绝大多数是"无结果"而非"变差"——变差多数可以带病修好，无结果才是死路信号。

## 反模式信号

- 数字差一点就整体回滚，丢掉了本可保留的大部分改进。
- 回滚后立刻原样重试同一方案。
