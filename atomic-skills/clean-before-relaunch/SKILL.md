# 重拉先清旧

**何时触发**：启动/重启服务、任务、监听进程之前。

## 规则

- 启动新实例前检查旧进程与端口占用；**先清理再拉起**。
- 清理动作幂等（对不存在的东西执行也不报错）；清理后等待退出确认（带上限的循环），确认退出后再启动。
- 启动失败时打印占用者信息（谁占着、从何时起），不只报"启动失败"。
- 反复拉起的尝试按序编号留痕，可追溯可对比。

## 反模式信号

- 端口被旧实例占着，新实例起来即崩，还被误判为代码问题。
- 杀完进程立刻启动，旧进程尚未完全退出，状态文件被两个实例交叉写。
