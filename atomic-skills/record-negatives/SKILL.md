# 否定记录保值

**何时触发**：每轮实验结束、每次踩坑解决、每个假设被否定时。

## 规则

- 每轮结束写 3 行：**改了什么 / 数值如何 / 结论**（含被否定的假设与原因）。
- 被否定假设的记录优先级**高于**成功记录——它防止下一轮、下一个会话重走死路；成功记录帮不了未来的失败，否定记录可以。
- 踩坑按"现象 → 根因 → 解法"编号入册，后续按编号引用而非重新调查。
- 新任务/新会话开始**先查册**；同一错误再次出现，说明册子没被接入流程，要修的是接入方式。
- 提交说明必须携带验证证据与实测数值，与验证记录挂钩。

## 数据画像

- 恢复的会话里反复出现"重新发现同一个 bug"——否定经验未沉淀是走回头路的第一大来源。

## 反模式信号

- 三轮迭代后没人说得清"哪些方向已经证明不行"。
- 同一个坑在不同会话里被独立踩了多次。
