# 修复后回归扫

**何时触发**：任何修复刚落地、准备宣布问题解决时。

## 规则

- 修复落地后重跑**此前已通过**的相邻用例，确认没有引入新失败——"修好 A 弄坏 B"是成串出现的模式。
- 补丁应用后观测**没有变化** = 假设错误：回滚补丁，重新归因；禁止叠加第二个未验证补丁碰运气。
- 出现过的回归建立清单，每轮修复后逐项核对。
- 修复的验证要覆盖修复针对的场景**和**它可能波及的场景。

## 反模式信号

- "修的是缓存问题，结果并发路径开始偶发错"——修复本身成了新 bug 源。
- 同一个问题修三轮，每轮都在补上一轮补丁的洞。
